# Historical Fundamental Snapshot Queries

This phase adds a read-only, query-time historical fundamental snapshot. It does
not change current/latest ticker snapshot output, snapshot files, report
generation, UI, scheduler behavior, SwingMaster state calculations, or database
schema.

## Current Snapshot Architecture

Current ticker snapshots are generated by
`swingmaster.cli.run_fundamental_ticker_snapshot`. They are CSV/stdout report
objects, not a historically materialized snapshot table.

Current builder behavior:

- `load_latest_quarter_rows`: latest `rc_fundamental_ttm` rows by
  `as_of_date DESC`, limited by `--quarters`.
- `load_quarterly_rows`: matching `rc_fundamental_quarterly` rows by selected
  `latest_period_end_date`.
- `load_stored_percentile_rows`: stored
  `rc_fundamental_score_percentile` rows for target dates.
- `load_stored_valuation_rows`: stored `rc_fundamental_valuation` rows for
  selected TTM `as_of_date` values.
- `load_latest_valuation_snapshot`: latest stored valuation row, independent of
  displayed quarter columns.
- Optional technical append sections read price behavior, Dow structure,
  candlestick, divergence, moving average, and technical relevance helpers.

The current snapshot is current-state display material. It is not keyed as a
historical research object and should remain unchanged.

## Dependency Map

| Section | Current selector | Historical-safe selector | Classification |
| --- | --- | --- | --- |
| quarterly values | selected TTM period end | quarter matching selected historical TTM | `HISTORICAL_SAFE_AVAILABLE` |
| TTM values | latest/report rows by `as_of_date` | `select_latest_ttm_as_of` effective date <= D | `HISTORICAL_SAFE_AVAILABLE` |
| score components | current TTM score columns | `select_latest_score_as_of` effective date <= D | `HISTORICAL_SAFE_AVAILABLE` |
| total score | current TTM score columns | effective-date-safe score row | `HISTORICAL_SAFE_AVAILABLE` |
| percentiles | stored percentile table | `calculate_ticker_historical_percentile_as_of` | `HISTORICAL_SAFE_AVAILABLE` |
| valuation | stored valuation rows/latest valuation | `calculate_historical_valuation_as_of` | `HISTORICAL_SAFE_AVAILABLE` |
| earnings metadata | implicit quarter/report context | selected TTM period/effective metadata only | `OPTIONAL_HISTORICAL_DEFER` |
| price metadata | latest price behavior helper | valuation selected close date <= D | `HISTORICAL_SAFE_AVAILABLE` |
| price behavior | optional latest helper | not included | `OPTIONAL_HISTORICAL_DEFER` |
| Dow/candlestick/divergence/MA/relevance | optional technical readers | not included in this phase | `DEFER_TO_STATE_INTEGRATION` |
| market/sector context | `ticker_meta` for percentiles | `ticker_meta` for historical percentile population | `HISTORICAL_SAFE_AVAILABLE` |

Vintage and field provenance tables remain disabled and unused.

## Contract

The new API is
`swingmaster.fundamentals.historical_snapshot.build_historical_fundamental_snapshot`.

Policy marker:

`LATEST_AVAILABLE_EFFECTIVE_DATED_FUNDAMENTALS_AS_OF_DATE`

Required fields include:

- `ticker`
- `requested_as_of_date`
- `snapshot_status`
- `fundamentals_policy`
- `source_ttm_as_of_date`
- `latest_component_period_end`
- `source_ttm_effective_trading_date`
- `source_score_as_of_date`
- `source_score_effective_trading_date`
- `selected_price_date`
- `score_percentile_population_size`
- `valuation_status`
- `missing_components`
- `warnings`

The snapshot includes TTM, score, quarterly, percentile, and valuation sections
when the historically safe inputs are available. Current/latest values appear
only under the optional `comparison` section.

## Source Rules

For requested date `D`:

- TTM: latest row with `effective_trading_date <= D`.
- Score: latest row with `score_effective_trading_date <= D`.
- Percentiles: query-time population where each peer uses its latest effective
  score row by `D`; current persisted percentile rows are not used as
  historical values.
- Valuation: latest historical close with `pvm <= D` plus latest TTM effective
  by `D`.

No component falls back to future-effective or current/latest data.

## Statuses

Statuses:

- `OK`
- `PARTIAL`
- `NO_AVAILABLE_TTM`
- `NO_AVAILABLE_SCORE`
- `NO_AVAILABLE_PERCENTILE`
- `NO_PRICE_AVAILABLE`
- `VALUATION_UNAVAILABLE`

Minimum usable data is an effective-date-safe TTM row. Score is required for a
complete snapshot, but the query returns a `PARTIAL` snapshot rather than
failing when score fields are unavailable. Percentiles and valuation are optional
enrichments.

Missing-data behavior:

- no TTM: `NO_AVAILABLE_TTM`, no usable historical snapshot sections;
- score unavailable: `PARTIAL`;
- percentile unavailable or disabled: core snapshot retained;
- valuation unavailable or disabled: core snapshot retained;
- no historical price: valuation unavailable, core snapshot retained.

## CLIs

Inspect one snapshot:

```bash
.venv/bin/python -m swingmaster.cli.inspect_historical_fundamental_snapshot \
  --fundamentals-db fundamentals_usa.db \
  --price-db /home/kalle/projects/rawcandle/data/osakedata.db \
  --ticker AAPL \
  --as-of-date 2026-04-30 \
  --market usa \
  --include-percentiles \
  --include-valuation \
  --include-current-comparison \
  --json
```

Audit a bounded set:

```bash
.venv/bin/python -m swingmaster.cli.audit_historical_fundamental_snapshot \
  --fundamentals-db fundamentals_usa.db \
  --price-db /home/kalle/projects/rawcandle/data/osakedata.db \
  --market usa \
  --as-of-date 2026-04-30 \
  --ticker AAPL --ticker MSFT --ticker JPM \
  --include-percentiles \
  --include-valuation \
  --output-root temp/fundamental_historical_snapshot/example \
  --json
```

Audit JSON, CSV, summary, and progress log paths are validated to stay under the
repository `temp/` tree.

## Performance

Measured on `AAPL` for `2026-04-30`:

- no optional sections: `0.0008s`
- percentiles only: `0.4017s`
- valuation only: `0.0003s`
- full snapshot: `0.4082s`
- 11-ticker full batch: `6.8306s`

Percentile calculation dominates query time. The current decision is
`QUERY_TIME_ONLY`. Event-date materialization or a separate research table can
be revisited if larger research batches require it. The current snapshot table
or report format should not be extended for historical semantics.

## State Integration

Historical snapshots are ready as query-time research inputs. The next phase can
decide how SwingMaster state or transition calculations should consume them,
but this phase intentionally leaves states, transitions, reports, UI, and
schedulers unchanged.

Known limitations:

- optional technical sections are deferred;
- no FX conversion is added for valuation;
- no vintage or field-level availability is used;
- PE and EV/EBITDA are not produced because the current valuation path does not
  implement them.
